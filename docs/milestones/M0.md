# M0 — Setup & môi trường

**Tag:** `m0` · **Máy:** Laptop Windows native (Docker Desktop, RTX 3050 6GB) · **Thời lượng ước tính:** 3–4 ngày

## Mục tiêu
Dựng một repo Python chuẩn production, chạy ổn định **trực tiếp trên Windows** và đồng thời xanh trên CI Linux. Dựng khung cho lớp LLM trừu tượng để mọi milestone sau gọi LLM theo một cách thống nhất. Thứ quan trọng nhất cần có cuối M0 là **số đo thật về VRAM và thông lượng của laptop**: mọi quyết định về model và ngân sách eval sau này đều dựa trên các số đó.

## Việc cần làm
1. **Cài công cụ trên Windows:** Git for Windows (kèm Git Bash), `uv`, Docker Desktop, Ollama for Windows, driver NVIDIA mới. Ghi các bước cài vào `docs/setup_windows.md`.
2. Khởi tạo package `antibros` (src layout) bằng `uv`, Python 3.11+.
   - Cấu hình PyTorch trong `[tool.uv.sources]`: CUDA wheel cho `sys_platform == 'win32'`, CPU wheel cho Linux (CI).
   - Pin bằng `uv.lock`.
3. **`.gitattributes`:** `* text=auto eol=lf`, `evalsets/** -text`, và đánh dấu file nhị phân. Cấu hình Git: `core.autocrlf=false`, `core.longpaths=true`.
4. Cấu hình ruff (bật rule cảnh báo `open()` thiếu `encoding`), mypy, pytest (marker `integration`, mặc định skip; chặn socket trong unit test) và pre-commit.
5. **Task runner `poethepoet`** trong `[tool.poe.tasks]`: `lint`, `format`, `typecheck`, `test`, `check` (gồm cả ba), `up`, `api`, `ui`. Không tạo Makefile.
6. Config loader: YAML → Pydantic (`AppConfig`, `ModelProfile`). Secret đọc từ env qua `pydantic-settings`. Tạo `.env.example`, trong đó `LLM_BASE_URL` mặc định là `http://127.0.0.1:11434/v1`.
7. CLI Typer `antibros`, có stub đủ các subcommand ở spec §11.
8. **Tiện ích I/O dùng chung** (`antibros.io`):
   - `read_text`/`write_text` luôn dùng UTF-8.
   - Ghi file atomic (file tạm + `os.replace`, retry khi gặp `PermissionError`).
   - Hàm kiểm tra tên file hợp lệ trên Windows.
9. **Khung `antibros.llm`:**
   - Interface `LLMClient`, `LLMResult`.
   - Provider `fake` (trả lời theo kịch bản, hỗ trợ structured output).
   - Cache trên đĩa, tên file cache theo hash.
10. **Xác minh model trên Ollama for Windows:**
    - Xác minh tag và quantization của các ứng viên ở spec §4.4 (`qwen3.5:4b`, `qwen3.5:2b`, `gemma4:e4b`, verifier).
    - Tạo `configs/models/{laptop,laptop_light,evalset_verifiers}.yaml`, ghi kèm digest.
    - Tắt chế độ thinking, rồi kiểm tra structured output với một JSON schema nhỏ.
11. **Driver NVIDIA:** đặt *CUDA – Sysmem Fallback Policy* = *Prefer No Sysmem Fallback* (nếu driver có setting này). Thử cố ý nạp quá VRAM để xác nhận hệ thống báo OOM thay vì chạy chậm âm thầm.
12. **Đo phần cứng** bằng `scripts/vram_probe.py`:
    - VRAM khi nạp từng thành phần: LLM với `num_ctx` 4096 và 8192, bge-m3 FP16, reranker FP16, và tổ hợp LLM + embedder + reranker.
    - Tốc độ prefill và tốc độ sinh token (token/giây) của pipeline LLM và judge LLM.
    - Ghi kết quả vào `reports/hardware.md`, kèm kết luận reranker chạy GPU hay CPU, và GPU nào đang lo hiển thị (iGPU hay RTX 3050).
13. **Qdrant:**
    - `docker-compose.yml` với service `qdrant` có healthcheck và volume.
    - Kiểm tra chế độ embedded (`vector_store.mode: local`) có hỗ trợ dense + sparse named vectors không; ghi kết quả vào `reports/hardware.md`.
14. `.github/workflows/ci.yml`: `lint` và `typecheck` (ubuntu); `test` theo matrix `windows-latest` + `ubuntu-latest`.
15. `.gitignore`: `data/`, `.env`, cache, `.venv`.
16. `scripts/env_report.py` (Python, không dùng bash): in hệ điều hành, GPU, driver, phiên bản CUDA, torch và Ollama, cùng digest model. Kết quả được ghi vào fingerprint.

## Acceptance criteria
- [ ] Trên laptop Windows, `uv sync` rồi `uv run poe check` xanh, trong cả PowerShell lẫn Git Bash.
- [ ] CI xanh trên cả `windows-latest` và `ubuntu-latest`.
- [ ] `uv run python -c "import torch; print(torch.cuda.is_available())"` trả `True` trên Windows.
- [ ] `docker compose up -d qdrant` cho trạng thái `healthy` trong Docker Desktop.
- [ ] `antibros --help` liệt kê đủ subcommand.
- [ ] Provider `fake` trả structured output đúng schema; có test. Test chặn socket chứng minh unit test không gọi mạng.
- [ ] Có test round-trip UTF-8 với chuỗi tiếng Việt có dấu, và test ghi file atomic.
- [ ] Đã có 3 file model profile với tag và digest đã xác minh; pipeline LLM trả JSON hợp lệ qua Ollama for Windows.
- [ ] `reports/hardware.md` có số đo VRAM và token/giây thật (không phải ước tính), cùng kết luận về cấu hình chạy được trong 6GB và trạng thái của setting sysmem fallback.
- [ ] Không có secret nào trong repo; không có file `.sh`/`.ps1` nào ngoài `docker/`.

## Câu hỏi tự kiểm tra
1. Vì sao dùng src layout thay vì flat layout?
2. Vì sao phải pin phiên bản PyTorch bằng lockfile? Làm sao một `uv.lock` chứa được cả CUDA wheel cho Windows lẫn CPU wheel cho CI Linux?
3. Config và secret khác nhau thế nào? Vì sao tách riêng?
4. Provider `fake` giúp được những gì cho test và CI?
5. Một cache key cho lời gọi LLM cần gồm những trường nào để không bao giờ trả nhầm kết quả? Vì sao tên file cache phải là hash, không phải chính key đó?
6. Nếu Git tự đổi LF thành CRLF khi checkout trên Windows, thì `evalset verify` và offset `char_start`/`char_end` bị ảnh hưởng thế nào? `.gitattributes` ngăn điều đó ra sao?
7. Vì sao phải ghi rõ `encoding="utf-8"` trên Windows? Cho một ví dụ lỗi cụ thể với tiếng Việt.
8. "Sysmem fallback" của driver NVIDIA trên Windows là gì? Vì sao một OOM rõ ràng lại tốt hơn việc chạy chậm âm thầm khi đo ngân sách thời gian eval?
9. `num_ctx` ảnh hưởng tới VRAM thế nào? Prefill và decode khác nhau thế nào về tốc độ?
