# M3 — Baseline RAG, LLM providers, API & UI

**Tag:** `m3` · **Máy:** Laptop (hồ sơ model `laptop`) · **Thời lượng ước tính:** 1 tuần

## Mục tiêu
Có một hệ thống **end-to-end chạy được**: hỏi → truy xuất → trả lời có citation → API → UI → trace. Hoàn thiện các adapter LLM để sau này **đổi sang OpenAI hoặc Gemini chỉ bằng config**, và mọi adapter đều được test offline. **Đo thông lượng thật** để xác nhận ngân sách eval 10–20 phút là khả thi.

## Việc cần làm
1. **Adapter LLM:**
   - `openai_compatible` (Ollama, llama.cpp, OpenAI) và `gemini` (`google-genai`).
   - Map JSON schema sang cơ chế structured output của từng provider; retry/backoff, timeout; đọc `usage`; tính cost từ `price_table`; tắt thinking khi model hỗ trợ; điều khiển `keep_alive` (để unload model giữa pha predict và judge).
2. **Test adapter offline:** mock HTTP và fixture response đã ghi sẵn, kiểm tra payload gửi đi, cách parse kết quả, và xử lý lỗi (429, 500, timeout, JSON hỏng).
3. **Generator:**
   - Structured output gồm `answer`, `claims[{text, citation_ids}]`, `status`.
   - Prompt nằm trong `prompts/` và bắt buộc: chỉ dùng context; mỗi claim có citation; trả lời bằng ngôn ngữ của câu hỏi; nêu rõ khi bằng chứng mâu thuẫn.
   - Citation được đánh số bằng code, rồi map ngược `[n]` → `chunk_id`.
4. **LangGraph tối thiểu (`baseline`):** `query_analyze` (phát hiện ngôn ngữ + dịch) → `retrieve` (hybrid) → `generate`. Mỗi node là hàm thuần, test được riêng.
5. **Judge:** các prompt chấm faithfulness, key-point coverage và citation precision/recall, qua wrapper RAGAS hoặc tự cài theo định nghĩa (ghi ADR nếu tự cài).
6. **Tracing** với backend `jsonl` (mặc định) và `langfuse` (tùy chọn).
7. **FastAPI:** `POST /ask`, `GET /health`, `POST /feedback`, theo schema ở spec §5.4.
8. **Streamlit:** ô hỏi, câu trả lời có citation, panel nguồn có badge evidence level, tab Debug.
9. `configs/baseline.yaml`.
10. **Đo thông lượng:**
    - Chạy `antibros eval predict` + `judge` trên **toàn bộ 16 câu dev** với `baseline`.
    - Ghi giây/câu của pipeline và judge, tỷ lệ JSON hợp lệ, VRAM đỉnh vào `reports/hardware.md`.
    - Ngoại suy thời gian cho test (32 câu) và cho `full`. Nếu dự báo vượt ngân sách §6.8, áp dụng danh sách xử lý khai báo trước, ghi ADR.

## Acceptance criteria
- [ ] Đổi `llm.provider` giữa `fake`, `openai_compatible` và `gemini` không cần sửa code; có test cho từng adapter.
- [ ] **Không có test nào gọi mạng thật** (kiểm bằng cách chặn socket trong pytest).
- [ ] Citation validity = 100% trên các câu đã chạy: mọi `[n]` ứng với một chunk có thật trong context.
- [ ] Hỏi được qua UI trên laptop; trace được ghi ra file `jsonl`.
- [ ] Chạy `predict` lần 2 trên cùng câu hỏi không gọi lại LLM (cache hit 100%).
- [ ] Run `baseline` trên dev (predict + judge) hoàn thành **≤ 10 phút**, có `timing.json`; tỷ lệ JSON hợp lệ được báo cáo.
- [ ] `reports/hardware.md` có số giây/câu thật và dự báo thời gian cho test.
- [ ] `leakcheck` pass sau khi thêm prompt.

## Câu hỏi tự kiểm tra
1. Vì sao citation phải được đánh số bằng code mà không để LLM tự đặt?
2. Structured output khác gì so với parse text tự do? Nếu model vẫn trả JSON hỏng thì xử lý thế nào?
3. Cần những gì để chuyển từ Ollama sang Gemini mà không đổi logic pipeline? Những khác biệt nào giữa các provider bị che bởi adapter?
4. Làm sao test một adapter API mà không cần API key?
5. Dịch query sang tiếng Anh có thể làm mất gì? Cho một ví dụ về thuật ngữ phòng gym tiếng Việt.
6. Vì sao mỗi node LangGraph nên là một hàm thuần?
7. Vì sao judge phải khác họ với pipeline LLM? Vì sao hai model không được nằm trong VRAM cùng lúc trên laptop này?
